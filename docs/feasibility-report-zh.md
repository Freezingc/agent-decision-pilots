## 先给判断

**目前没有一个候选机制通过“明显强于简单基线、值得直接投入数月”的门槛。** 本轮实际完成四个方向的最小验证，并对最值得保留的恢复问题追加了一轮独立种子实验。结果多为负面：问题存在，但初始方案的收益容易由简单规则、冗余阶段或已知模型假设解释。

这不是四个问题都没有研究价值，而是应停止把“加一个规划器／置信度阈值／跳步控制器”直接当作论文创新。现阶段应保留实验基础设施，停止这四种具体机制的扩量和大模型训练；如果继续选题，我优先保留 **信息不完整时的工具状态诊断**，但需要把问题改成可识别性、参数学习与主动检查选择，重新检验新颖性。

本轮没有付费 API。真实本地模型共 **956 次调用**：跳步 768 次，记忆有效批 84 次，作废适配预检 104 次。总输入 **208,105**、输出 **51,749** token；作废批计入真实消耗，不计入效果。CPU 模拟、重跑、沙箱和本地 GPU 也有资源成本，不能写成“实验成本为零”。

## P1：真正值得追问的是“现在知道多少”，而非重试提示怎么写

具体问题是：一次写入超时后，返回通道失败，但动作可能已经执行；检查读到旧状态，也不等于动作从未发生。重复调用可能造成不可逆副作用。

已有 [Verified Tool Calls](https://arxiv.org/html/2608.02645v1) 已提出先验后重试、幂等键，并在第 8 节明确提出融合置信度来选择等待、检查、重试或人工介入。因此，“用置信度选择恢复动作”不足以构成新的贡献。[鲁棒 POMDP](https://proceedings.mlr.press/v37/osogami15.html) 和 [IJCAI 2024 的不确定性语义分析](https://www.ijcai.org/proceedings/2024/740) 也表明，模型集合与保守规划本身早已有系统研究。

首轮把隐藏状态设为执行次数及剩余可见延迟，所有策略只看动作与观测历史。参数匹配时，低故障、低检查成本下规划器成功 595/600、重复 0，固定规则 594/600、重复 0，平均动作成本 0.8698 对 0.9672。但把真实延迟变长，二者重复均达到 350/600。更多成功有时还伴随虚报完成，故不能只报成功和节省。

随后实际增加 robust-v2：新 seed `2026101902`，12 条件、7 方法、50,400 测试 episode；在看新测试结果前冻结模型集合和门槛，补齐同风险门槛的单模型消融、更完整固定规则与同信息后验阈值规则。

补测的关键反例是低故障／检查成本 1：集合内长延迟时，保守模型集合策略能够避免单模型门控的 363/600 次重复；但它与开发集选出的质量匹配固定规则完全一致，都是成功 599/600、重复 0、虚报 1、成本 2.644。集合外更长延迟下，二者都重复 412/600。另一些条件保守规划直接全部弃权。这说明模型覆盖有作用，却尚未建立复杂规划的增量，也没有建立未知漂移下的安全性。

目前实现的门槛是：

`仅当所有声明模型下 P(已经执行 | 历史) ≤ ε重复 时允许重试`

`仅当所有声明模型下 P(尚未执行 | 历史) ≤ ε虚报 时允许接受完成`

这是依赖所声明模型的后验条件，不能当作无条件频率风险保证。算法假设、集合外失败、弃权和原始轨迹见 [首轮记录](p1-notes.md) 与 [补测记录](p1-robust-notes.md)。

**如果继续，新的核心问题应收窄为：如何从有限、被策略选择过的工具日志中学习可见性延迟的不确定性，并主动选择能区分“未执行”和“执行未可见”的检查。** 单一存在性读在任意未知长延迟下不能完成这个区分；不能指望换一个更大 LLM 就解决信息缺失。

可能的算法贡献应至少包含一个明确的新成分，而不是现有模块拼接：动作相关的可识别状态表示；对删失／选择偏差日志学习延迟尾部的不确定性；用执行风险而非单纯熵下降选择下一次检查；或建立带明确假设的有限样本风险界。普通 Bayes、minimax、置信阈值和幂等键都必须作为强对照。

## P2：先保证“应该更新”是一个能被数据检验的问题

一个可研究的表示是把记忆拆成 `(主体, 属性, 条件, 生效时间, 来源)`，旧事实不用立即破坏性覆盖。新证据触发替代、条件并存或暂存；决策目标应看未来任务受损，而不是仅看当前句对分类准确率。

本轮采用 [MemConflict 官方数据](https://github.com/TaoZhen1110/MemConflict)，固定 commit 和完整文件 hash。原始数据本身是 LLM 辅助构造对话，不能称为自然用户数据。首批 104 对在审查中发现出生地／居住地、第三人／本人混淆，已作废隔离；修正后的 84 对只保留原文直接支持的关系。

但干净批仍有决定性缺陷：正例都是住所变更，负例都是条件偏好。简单第一人称搬迁词规则就能测试 52/52 全对。模型直接判断和保守阈值均只正确 43/52，说明该切片没有验证置信决策算法的能力。模型覆盖率 45/52，漏更新 3/26；“零误覆盖”不能掩盖暂缓和漏更新。

可继续的创新候选应是 **考虑下游损害的非破坏性记忆更新与定向追问**。最低验证要有同一属性、相似词汇的真更新与应保留例子，并设置实际记忆库和后续查询；与最新优先、带时间戳检索、同覆盖率置信阈值、保留所有版本比较。先做 50–100 对经过盲审的匹配难例，若强规则仍全解或结果仅靠大量拒绝，则停止。当前尚未完成这一步，不能把它写成有效新方法。

来源未明确声明再分发许可，所有对话原文只保留本机。详见 [P2 记录](p2-notes.md)。

## P3：先证明需要组合控制，再研究如何学习组合控制

候选创新应是学习“步骤对子在什么状态下发生交互”，而不只是为各步骤独立打分。可用稀疏干预图或低阶交互模型避免枚举所有子集，再把整条执行路径的降质风险作为约束。

[Learning What to Skip](https://arxiv.org/html/2609.30734v1) 第 4.3 节把策略限制为一次有效干预，避免依赖未观测的组合路径。因此多次干预确有明确的对照对象；但不能仅把动作空间变大就认定有贡献。

本轮三阶段流程为初答、公开样例反馈修复、终审修订。两个可跳节点都可修改最终代码。768 次生成全部有真实响应，隐藏标签在推理完成后才加载。开发与测试各 48 个题，每题两个采样种子，测试总计 96 个实例。

测试的四路径复杂门控与“公开样例通过便停止，否则修复”完全一致：75/96，通过率与开发选出的固定修复路径相同，平均输入加输出 token 从 530.09 降到 242.24。相对完整流程 829.69，节省 70.80%；但这只是简单早停，未发现复杂算法收益。96 个测试实例中 86 个四分支源代码完全相同，仅 1 个成败模式有非零二阶交互。

这里最容易犯的错误是把“多调用了两个无用阶段”人为造出的节省写成方法优势。实际结果应解释为 **最小强基线已经足够，当前工作流不适合验证组合创新**。下轮只有在更有依赖的真实工作流中发现简单早停无法利用的空间，才值得研究稀疏组合信用；本轮不以换更复杂提示来追求正结果。详见 [P3 记录](p3-notes.md)。

## P4：澄清决策需要证明非短视收益

候选机制是明确区分环境信息和用户偏好，让探查与提问有不同观测模型、成本和隐私／打扰代价。核心假设是二者互补，单步信息价值会错过“先查后问”的好路径。

本轮刻意把两个信息来源分开，运行 45 条件，并在首轮后补上更强的不调参单步规则和已知模型精确期望诊断。结果是 43/45 条件两步规划与单步规则完全相同，剩余最大增量为 0.00077037 效用单位。有限样本中看似较大的优势主要来自开发调参规则选差了，不能归因于复杂规划。

因此停止当前二元模拟向真实用户扩展。今后若改题，需要真实任务中有必要的互补信息、不可逆行动或延后澄清损失，并与同信息的强单步规则比较；先检查机制空间，随后才值得付真人标注成本。详见 [P4 记录](p4-notes.md)。

## 下一步只保留一个小关卡

**优先顺序是恢复状态诊断，其次是重新设计记忆难例；当前跳步和澄清机制停止。** 这只是问题选择优先级，不是已经找到正结果后的主线立项。

恢复方向下一关限定为 2–3 天、零训练：做一个本地小型真实状态服务，提供两到三类只读检查，例如缓存存在性、带操作 ID 的状态、字段完整性。隐藏故障包括请求未执行、已执行但缓存未刷新、部分写入；模型只看公开工具响应，终态由服务真实存储判定。

算法候选根据历史和检查成本选择下一次检查，估计“当前证据是否足以授权不可逆动作”。对照包括最佳固定检查顺序、指数退避、保守后验阈值、已知模型的贪心信息价值、支持幂等键时的直接幂等重试。若状态端点或幂等键已解决问题，应如实采用工程方案，不再训练控制器。

继续条件事先限定：在相近成功／重复／虚报／弃权水平下，新方法相对最强固定或单步规则仍有至少 10% 的总检查成本空间，并在新任务模板和未见延迟分布保持；10% 是选题用的实用阈值，不是统计显著性界。先做上限和规则诊断，再决定是否需要学习。若只知道生成参数时有效、靠大量弃权安全、或贪心顺序已足够，立即停止这一版本。

本报告已经完成用户要求的首轮动手筛选与一次后续推进；上述真实状态服务属于下一项尚未执行的研究关卡。没有把它冒充已完成结果，也没有启动长期训练或付费调用。
