## 决定

**保留简单早停基线，暂不以联合跳步算法立项。** 本流程确有大量可省的 token，但开发集选出的复杂门控完全退化为“初答通过公开样例就停止，否则执行一次修复”。复杂门控与此简单规则的动作、输出、成本逐实例完全相同。大幅节省不能当作新的算法贡献。

本结果只限制该小模型、短代码题及三阶段流程；不否定长流程中存在组合干预问题，也不证明任意双跳都安全。

## 冻结数据、模型及四分支

数据是 EvalPlus MBPP+ v0.2.0 的 378 题发布版，原始 JSONL SHA256 为 `b54e762755248ca411b523c917fa9f93c07b5ff2966bf60b3917b853926a3dad`，评估器为 evalplus 0.3.1。复用旧项目的公开题面投影，未复用旧候选代码、判分或训练标签。先排除旧项目已经分析的 e0/e1 题，从剩余 218 题按 `SHA256("p3-v0|"+task_id)` 选 96 题，前 48 开发、后 48 测试。任务与种子不跨集合；这里的 heldout 是相对于本地实验，不能保证模型预训练没见过 MBPP。

每题两个独立初答种子，共 192 个实例；每实例四次实际生成，共 **768 请求**：

| 路径 | 实际执行 | 末端代码 |
|---|---|---|
| 00 | 初答 | 初答 |
| 10 | 初答 → 公开样例反馈修复 | 修复代码 |
| 01 | 初答 → 终审修订 | 终审代码 |
| 11 | 初答 → 公开样例反馈修复 → 终审修订 | 修复后的终审代码 |

修复和终审均输出完整代码，均有能力改变最终答案。初答及修复前缀在采集时共享，但每条策略按其完整路径计 token。两个终审分支使用同一个随机流，以降低随机性混杂；两次采样仍不足以识别一般性的确定因果交互。

本地模型 Qwen2.5-Coder-7B-Instruct，revision `c03e6d358207e414f1eca0bb1891e29f1db0e242`，temperature .7，top_p .95，每次最多 384 新 token，batch 16，bfloat16。GPU 2 独占本次进程；未使用付费 API、未改变模型权重。后端是已有的本地自回归实现，不声称与 vLLM/其他解码器逐 token 等价。

输入只含公开题面、当前代码和公开样例的沙箱执行状态。生成进程不加载参考解或隐藏输入；全部推理结束后才单独加载官方数据，在 bubblewrap 隔离进程中调用官方 EvalPlus 内核，联合要求 base 和 plus 都通过。相同题、相同源代码 hash 只评一次，768 个分支对应 210 个唯一代码评价；未把缓存命中当成新生成。

## 强对照及结果

门控只读“初答公开样例是否全部通过”和初答输出长度。开发集枚举 pass/fail 路径及四个长度阈值；以开发成功数不低于完整流程为约束选最省 token 的规则。另冻结同特征同网格的最多单跳门控（只准 10/01/11）、无长度特征的简单早停和开发选择的固定路径。这个经验约束不是总体风险保证。

测试为 **48 个独立题、每题 2 次采样，共 96 个实例**。不能把它写成 96 个独立题。

| 方法 | 通过 / 96 | 通过率 | 平均输入+输出 token | 平均输出 token |
|---|---:|---:|---:|---:|
| 固定初答 00 | 74 | 77.08% | 193.49 | 66.95 |
| 固定修复 10（开发选中的固定路径） | 75 | 78.13% | 530.09 | 133.91 |
| 固定终审 01 | 73 | 76.04% | 493.99 | 133.95 |
| 完整流程 11 | 73 | 76.04% | 829.69 | 199.99 |
| 开发选中的最多单跳门控 | 73 | 76.04% | 499.23 | 134.44 |
| 开发选中的四路径门控 | 75 | 78.13% | 242.24 | 79.38 |
| 简单公开样例早停 | 75 | 78.13% | 242.24 | 79.38 |

四路径门控为通过公开样例时选 00，否则选 10；测试 85 次初答早停、11 次修复，没有一次执行终审。相对完整流程输入加输出 token 下降 70.80%，相对开发选出的固定修复路径下降 54.30%；输出 token 分别下降 60.31% 和 40.72%。不能把输入与输出 token 等价相加后的节省率解释为 API 价格、GPU 时间或端到端时延节省。

相对完整流程，观察到 0 次逐实例降质、2 次改进。按题聚类 bootstrap 的平均通过率差 95% 描述区间为 [0,5.21] 百分点；平均 token 节省区间 [541.11,635.06]。相对固定修复，所有测试实例的成败相同，平均 token 节省区间 [254.77,321.08]。零降质事件及退化区间不构成非劣效检验、罕见错误率认证或分布外保证。

四位结果按 00/10/01/11 排列：72 个 `1111`、21 个 `0000`、2 个 `1100`、1 个 `0111`。只有 1/96 个实例有非零二阶成败交互；没有“仅初答对、其余三路全错”的实例。86/96 个实例四分支的源代码 hash 完全相同。这表示当前流程主要暴露冗余和少量终审损坏，未提供复杂组合决策的充分试验场。

85 个通过公开样例的初答中，有 11 个没通过隐藏测试。因此“公开样例通过便停止”是本测试集上的有效基线，不能作为普遍正确性的证书。四路径 oracle 与受限 oracle 均最多通过 75/96；oracle 读取隐藏标签，只是上限诊断，不是可部署算法。完整成败模式和新增覆盖见 `diagnostics.json`。

## 成本、修改和验证边界

有效采集总计输入 **163,911**、输出 **47,162** token。保存了 384 条完整公开样例执行反馈；门控路径至少需要执行初答公开样例，不能把工具 CPU 开销算作免费。中断过程中尚未完成的系统工作不包含在这 384 条收据里。完整采集的资源消耗和部署某条路径的逻辑 token 成本是两种不同计量。

初始运行在修复生成结束、尚未进入终审和隐藏评价前中断，用于统一两个终审分支的随机流；初答与修复响应完整复用，未重复调用。原日志在本地归档。`frozen.json` 保留该修订及当时源码 hash。隐藏结果读取前，另补上同特征的单跳门控、无长度门控与同完整成功条件的 oracle；新增源码 hash 及说明保存在 `source-evaluation-sidecar.json`。`diagnostics.json` 是结果后的解释性检查，没有据此重调任何策略。

5 个行为测试验证路径成本、按题隔离、门控不读隐藏标签、成败交互计算及终审共用随机流。推理收据 768/768 均与请求 hash、阶段种子相符，0 语法错误、0 截断。原生子任务在隐藏评价前做过只读科学审计；发现的强对照和证据链缺口已记录并补齐。这不是不同团队、不同模型的独立盲审。

## 复现

从项目根目录，使用互不重叠的新输出目录；先 prepare，再 generate，推理完成后 evaluate、analyze。生成需 CUDA 和模型缓存；评价需 Linux bubblewrap 及 evalplus 0.3.1。

```bash
PYTHONPATH=src python -m agent_pilots.workflow prepare --output artifacts/p3-new
PYTHONPATH=src CUDA_VISIBLE_DEVICES=2 python -m agent_pilots.workflow generate --output artifacts/p3-new
PYTHONPATH=src python -m agent_pilots.workflow evaluate --output artifacts/p3-new --workers 8
PYTHONPATH=src python -m agent_pilots.workflow analyze --output artifacts/p3-new
```

本机实际使用两个已有虚拟环境：`/home/zhangyudong/FDU/paper/Eval/.local/generation-venv/bin/python` 运行生成，`/home/zhangyudong/FDU/paper/Eval/.local/eval-venv/bin/python` 运行准备、评价与分析。模型和数据路径可在配置/命令参数中指定；原任务列表、分支响应、成本与判分结果随私有仓库保存，第三方记忆对话原文不在版本控制中。

最低立项门槛应是：更有意义、彼此有依赖的节点仍存在简单早停无法利用的空间；冻结的联合控制在独立题与更换工作流后仍有增量；逐任务降质风险与全部工具开销均可接受。当前这一版本未通过这些门槛，不据 70.8% 的表面节省继续扩量。
