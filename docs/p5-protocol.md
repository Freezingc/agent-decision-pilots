# P5：真实存储服务上的主动状态诊断可行性筛查

材料护照：2026-10-20；原创受控实验；代码与本地 HTTP/SQLite 服务；无参与者、无生产服务日志、无付费模型调用。沿用上一轮已提出且用户要求继续的实验。该轮是算法空间上界筛查，不是学习算法效果或新颖性的证明。

## 问题与阶段决策

写请求返回超时后，只读缓存、操作日志、主库字段检查的成本和可见延迟不同。即使给控制器准确的故障概率和延迟分布，多步主动选择检查是否还能明显胜过简单工程规则？若连这一有利上界也没有实用收益，就不训练延迟模型、不增加 LLM 调用。

先冻结以下设计，再编写控制器并读取结果。服务端实际通过独立进程、HTTP 和 SQLite 执行写入、部分写入、延迟发布和修复；故障与逻辑时间人为控制。每步推进一个逻辑时间单位，不把它称为实测生产网络延迟。

## 隐藏情景与公开能力

原写有三种结果：未受理 0.20、最终完整写入 0.65、最终只写第一个必需字段 0.15。完整和部分写入的落库时刻分布不同。名义环境分别为完整 `0/.50, 2/.35, 5/.15`、部分 `0/.10, 2/.30, 5/.60`；缓存附加滞后 `0/.40, 3/.60`，日志附加滞后 `0/.60, 2/.40`。移位环境分别为完整 `0/.20, 3/.30, 9/.50`、部分 `0/.05, 3/.20, 9/.75`；缓存滞后 `1/.25, 5/.75`、日志滞后 `0/.30, 4/.70`。条件于结果，其余滞后独立。

每种环境有 25 个加权原子情景，全部枚举。三个公开日志能力为原子状态日志（未受理、在途、完整、部分）、延迟状态日志、没有日志接口。所有情景均可通过缓存查存在、主库查完整字段、等待。最大 10 步；重试和修复各用一步。非幂等重试可能撞上未来才执行的原请求。已观察到记录 ID 后可修复同一行，修复不新建记录。终止后裁判执行全部未完成事件，再核实业务状态，防止漏算在途重复写。

两个公开成本配置：状态查询便宜时 `cache=.5, journal=1, fields=4, retry=1, repair=4`；主库与修复便宜时 `cache=.25, journal=3, fields=2, retry=1, repair=1.5`。每个行动再计逻辑延迟成本 .2；等待没有额外调用费用。成本是预设单位，不是人民币或真实 API 账单。另单列原接口支持幂等键的直接重试基线。

控制器只能读取工具公共响应。情景配置与终局数据库审计只由 runner 管理。操作、记录 ID 不编码隐藏标签。模板字段使用 reservation、invoice、shipment 三种结构；其作用是检查控制抽象是否跨字段结构正确，不足以证明自然任务或 LLM 泛化。

## 算法与强基线

1. 准确模型、全 10 步有限时域后验规划，作为此有限问题的理想上界。只在明确完整响应后声明完成；看到记录 ID 可修复；后验未受理概率至少 .99 才可非幂等重试。
2. 准确模型的一步信息价值规则：比较当前安全终止与一次检查后安全终止的费用，逐步重算。
3. 截止时刻规则及一步 rollout：使用模型支持内的最晚落库时刻安排主库检查，在此基础上逐步比较提前检查。防止把“会等待”本身包装成算法增益。
4. 强固定顺序库：枚举检查顺序、初始等待、固定/指数间隔、缓存命中后立即修复或继续检查；按准确模型的全情景期望损失选最优。选参不受有限开发集噪声影响，是偏向基线的比较。
5. 保守后验规则：按公开成本排序选择检查，使用相同重试与完成规则，明确处理部分写入。
6. 日志可原子查询、原写可幂等重试时的工程基线分别报告。另用名义模型规划器面对移位环境，展示模型错误风险；此结果不用于事后改参。

所有方法使用同一公共响应模型、能力、风险门槛与预算。放弃损失固定为 50，用于规划与固定规则选择；报告成本与成功/重复/错误完成/放弃，不用单一加权分数掩盖质量差异。没有新学习算法或算法创新声明。

## 评估和继续门槛

全枚举计算预设分布下的加权期望，再逐原子通过实际 HTTP/SQLite 服务核验模型和轨迹。主要比较剔除幂等特例后，两个延迟环境中分别对六个能力/成本条件等权平均的总成本。准确模型规划必须较最强质量相当基线节省至少 10%，两种环境都满足，成功率不低于基线 1 个百分点，重复/错误完成均不增加，放弃率不增加，才继续考虑从右删失日志学习模型。10% 是资源投入筛选标准，不是统计显著性阈值。

全枚举没有蒙特卡洛抽样误差，不计算虚假的样本置信区间；枚举数量也不是独立真实任务样本量。模板分别运行，报告原始加权结果与政策动作差异。记录每个 HTTP 响应、逻辑成本、控制器选择和实际终局数据库状态，另记真实服务请求耗时与规划时间作为基础设施指标。

若跨分布继续门槛未过，停止该版本的学习与大规模训练；若发现可解释的局部收益，保留其条件，不据此更改本轮门槛。若服务与预测不一致，先按独立验证失败处理，不把出错结果解释为算法优劣。

## 可复现性

运行前输出冻结 JSON、代码哈希、UTC 时间与固定规则选择结果。所有数值结果只来自随后运行。保存逐步压缩轨迹、期望策略表、服务核验、运行日志及清单；独立审核响应/状态/代价对应。实验命令设硬超时并监控进程与日志。使用现有 eval-venv 的 CPU 环境，不占用 GPU。

## 实施前的精确定义补充

此补充在读取实验结果之前加入，回答独立设计审查的三个缺口。没有改动已定分布、门槛或费用。

- 所有 `cache/journal/fields/wait/retry/repair` 先推进 tick 一次，执行该时刻所有到期原写与可见性发布，再执行行动。原写 delay=0 在创建 episode 时提交。缓存只返回 absent 或 present+记录 ID。主库返回实际行及字段。延迟日志在发布前一律 unknown，不把 unknown 等同未执行；发布后返回 complete/partial+ID。原子日志未受理返回 not_found、已受理未落库 pending、落库才返回 complete/partial。没有日志接口返回 unavailable。
- 重试在本步同步新建完整行；非幂等原请求的未来写入不取消。幂等键使两个写入合并同一行，后到部分写也不能删除已完整字段。修复只对已经公开观察到的 ID 补全原行。二者响应都可证明本次提交完整，但非幂等重试的响应不能排除未来重复。服务拒绝非法修复并回滚事务；本轮合法策略不会依赖该分支。
- 固定规则域为：所有可用检查的一、二、三元素无重复有序排列；初等等待 `(0,1,2,4,8)`；间隔 `(1,2,4)`；固定/指数间隔；缓存命中立即修复/转主库检查。看到完整证据立即 accept，看到字段或日志的 partial 立即 repair，同一后验风险门槛允许 retry；否则按固定时间表行动，预算耗尽放弃。公布规则总数和被选规则。
- 一步 VOI 在子节点计算所有安全直接结束方案，包含 repair/retry 的下一步费用、一步预算及原写未来重复风险；不把需要修复的部分写排除。一步 rollout 使用同一后验与截止时刻策略作为后续：等到剩余支持内最晚原写落库时刻做主库检查，随后 accept/repair/retry。逐步重算；也比较直接终止。整个有限时域最优使用同样行动、门槛与代价。
- 若在假设模型外出现零似然的公共历史，不重写似然、不偷看隐藏配置，立即放弃并记录 model_miss。名义模型面对移位环境是预先指定的压力测试。
- 每个原子情景以其预设概率为分母贡献期望。success 是控制器声明完成且终局恰有一行、所有必需字段正确；放弃后自然完成不计成功。duplicate 是冲刷后记录数大于一，与是否放弃无关。false_completion 是声明完成但终局业务条件不成立，可能与 duplicate 重叠；abstention 是未声明完成。所有结果保留四个指标。逻辑成本在控制器终止时截止，裁判冲刷不增加行动费用或延迟。放弃损失 50，重复写额外损失 200（用于选策略，不能替代单列风险）；非幂等 retry 的后验风险计入其期望损失。
- 在每个能力×成本单元内，比较满足相对 optimal 成功率差不超过 1 个百分点、重复/错误完成/放弃均不增加的最便宜基线，形成强基线包络。质量条件逐单元核实；再在每个环境六单元等权平均成本，要求两个环境各至少节省 10%。幂等直接重试另列，不与非幂等环境混算。
- 精确规划的标量目标不是一般的风险约束 Pareto 上界。只有当其在所有正概率情景中成功率为 1、重复/错误完成/放弃均为 0 时，期望 loss 恰等于 cost，才能据精确最优性判断相同零风险可行策略的成本空间。否则，本轮只能筛查该罚值下的版本；必须再做约束/Pareto 核查才能给出“算法空间不足”的结论。不得把罚值引起的保守放弃称为已证明没有改进空间。
