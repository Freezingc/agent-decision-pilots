# P5：真实存储服务上的状态诊断实验

## 材料护照

2026-10-20，北京时间。原创受控可行性筛查；已实际执行独立进程 HTTP/SQLite 服务；故障概率、落库时间和缓存／日志延迟均人工设定。控制器没有调用 LLM。主试 7,650 个执行 episode、41,484 次行动 HTTP 请求、0 次付费 API、0 GPU。逐情景枚举不是独立真实任务样本，不报告抽样置信区间。

## 决策

**停止“准确状态后验＋多步检查规划”这一版本的模型学习与大规模投入。** 给控制器准确的故障分布，10 步精确规划相对强简单基线包络，在名义／长延迟环境仅省 **1.38%／2.64%**，两者都未达到执行前冻结的 10% 实用门槛。这个判断限定于本服务及其预设分布，不是证明工具状态诊断永远不值得研究。

真正需要保留的问题是**有限公共观察能否支持非幂等重试**：名义模型直接用于长延迟环境，五个能力／成本条件中，重复写入及错误完成的加权概率均为 **43.75%**。这些错误没有触发零似然检测；一个看起来完全符合旧模型的否定历史，也可能使控制器过早认定原写未被受理。另一个条件触发零似然，转为 43.75% 放弃。它们是预先指定压力测试的结果，不能拿成功分支重算分母。

## 具体做了什么

服务端真实持久化原写、部分写入、缓存表、操作日志表和待执行事件。写请求初始化统一返回 timeout，控制器只能看三类检查的公共响应：缓存是否有记录、日志所示操作状态、主库行和必需字段。控制器可等待、修复已观察到的记录、重试、声明完成或放弃。每步推进一个逻辑 tick，行动后真实写入 SQLite；终止后裁判再处理全部未来事件，检测重试与在途原写的重复。

完整写／未受理／部分写的先验为 .65/.20/.15。两个延迟环境、三种日志能力、两种公开成本、三个字段模板共 36 个条件。每环境枚举 25 个加权原子，方法面对相同原子。三个模板只检验字段结构适配，不是自然任务泛化样本。完整分布、时间顺序、风险及门槛见 [执行前协议](p5-protocol.md) 和 `artifacts/p5/run-v1/frozen.json`。

强基线包括一步信息价值、等到模型支持内最晚落库时刻再查、基于该截止策略的一步 rollout、保守后验规则，以及固定顺序／等待／指数退避／修复分支的完整规则库。每个有日志的条件枚举 900 条固定规则，无日志条件 240 条；共 8,160 次规则候选评估。规则使用准确模型的全情景期望选参，避免用较弱的有限开发集选择制造规划优势。每单元在质量相当基线中取最便宜者形成包络。原接口支持幂等时的直接同键重试单列，不混入非幂等比较。

规划的目标是费用＋50×放弃＋200×重复风险，一般不能据此宣称解决风险约束下的成本最优。此次准确模型规划在每个正概率原子都完整成功、零重复／错误完成／放弃，因此目标恰等于费用；这才允许把其精确最优性解释为本行动限制内零风险策略的成本空间。不是一般的 Pareto 最优证明。两个准确模型分别重新规划，也不是学习后跨分布泛化。

幂等能力可用时，直接同键重试在所有预设情景均完成，成本 **1.2**、一步、无重复；服务保证后到部分写不会抹掉已有完整字段。该结果依赖强幂等／合并语义，不表示所有真实 API 都能这样修复部分业务事务。不同服务能力的结果仅作工程取舍对照。

## 分布失配揭示的问题

在名义模型中，原写最迟 tick5 落库；长延迟环境则有大量原写到 tick9 才执行。过了旧模型的最晚时刻仍查不到，后验可能确信原写未受理，允许非幂等重试。原请求在重试步开始或其后照常落库，终局变成两行。例如无日志／主库便宜条件下，tick8 读缓存仍无记录，控制器授权 tick9 重试；服务先执行当步到期原写、再执行重试，最后两行均完整，业务条件仍失败。虽然每一步响应都在旧模型的可能集合内，“没有零似然”也不能证明模型仍正确。

| 名义模型用于长延迟环境 | 成功 | 重复写／错误完成 | 放弃 | 零似然 model_miss |
|---|---:|---:|---:|---:|
| 原子日志、S | 56.25% | 0 | 43.75% | 43.75% |
| 其余五单元，各自相同 | 56.25% | 43.75% | 0 | 0 |

这不是已学习控制器的实测缺陷，也不是证明贝叶斯推断本身错误：前提模型的支持范围错误。更不能把客户端超时直接标成“执行时间大于超时阈值”的右删失标签；写入可能早已发生，只是响应没有返回。状态是否已提交与哪个检查何时可见，需要分别建模。来源核查记录了已有删失学习、等待策略和多通道诊断的近邻。

## 后续方向的取舍

不继续训练一个更复杂的检查规划器：当前理想信息下的总收益空间已经小。也不把泛称的“后验状态＋风险重试”写成创新，[Verified Tool Calls §8](https://arxiv.org/html/2608.02645v1#S8) 已明确提出融合多信号并选择重试、等待复核、介入或终止；[Learning to Wait §2](https://arxiv.org/html/2512.16262v1#S2) 也已有根据执行历史调整检查时刻的工作。

更窄的待检验假设是：**把不可识别的状态保留为集合，通过有成本的终局审计或能力查询缩小集合；仅当集合中的每个可行解释都允许重试时才授权写操作。** 这与稳健 POMDP、主动诊断、可靠系统设计有明显重叠，本轮没有证实算法新颖性。真正可能的贡献必须落实到：有限预算下该向哪些操作购买额外审计、如何校准遗漏长尾的风险、以及比历史分位数／单步审计规则多获得多少安全完成。需要有独立终局标签的真实或更自然工具日志，不能继续只换模拟器参数。

### 附加机制验证：有限观察的观测等价

主试后按预定补充协议枚举两个世界。A 中 80% 在 tick2 完整落库、20% 未受理；B 中 80% 同样在 tick2 完整落库、20% 到 tick9 才落库。两世界的短分支和歧义分支权重分别同为 4/5、1/5。检查用全部 1,024 种长度为 5 的只读动作序列，对每个分支和世界实际创建独立服务 episode，共 4,096 主轨迹、2,048 对历史；规范化随机 ID 后，所有公共响应逐步完全相同，没有删除任何非 ID 字段。

在歧义分支第六步非幂等重试并冲刷终局，A 得到一行，B 得到两行；短分支在两个世界都重复。五步后放弃时，控制器两个世界都不声明成功，但最终 A 没有行、B 有一行自然完成，说明裁判终局也不能倒算成控制器已完成。一次 atomic 日志读取可区分 `not_found` 和 `pending`；稳定幂等键重试则让两个世界都只有一条完整记录。

附加运行含 4,106 条 episode、28,740 次计时 HTTP 请求，44.95 秒，0 请求失败；关闭请求另有 1 次但未计入计时。SQLite 原始文件 7,376,896 字节，并以 SHA-256 确认 gzip 解压逐字节相同。准确复现与局限见 [探针协议](p5-identifiability-protocol.md)、`artifacts/p5/identifiability-v1/verification.json` 和清单。它展示人为构造的有限观察等价，不是现实世界比例估计、不可识别性普遍定理或新算法结果。

执行附加的观察等价探针是为了检查主试失配机制，不用于替主试“翻盘”。其结果单独保存，不能与主试合并成新的成功率。
